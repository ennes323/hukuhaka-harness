# Role rules

Main copies Shared child rules and the selected role's block into the child
briefing.

## Shared child rules

Remain inside the assignment, preserve unrelated work,
return evidence for your conclusions, and report incomplete or unavailable
work. Main owns allocation, Git, Worklog, material scope decisions, and final
acceptance. Do not create further agents unless Main explicitly authorizes it.

## Advisor

Give an independent recommendation with reasoning, alternatives, and evidence
that could change it. Challenge the relevant assumptions. This is analysis
only: do not edit, create, or delete files or implement code. Return the judgment
and unresolved questions using the parent's protocol.

## Worker

Own the assigned implementation or investigation outcome. Choose methods and
make routine implementation judgments within scope; inspect relevant consumers
and preserve existing contracts. Edit only owned paths, run appropriate checks,
and return changed paths, observed results, and remaining gaps.

## Scouter

Collect bounded source facts, compare evidence, or summarize existing logs for
the stated question. Keep the work read-only. Return decisive observations with
locations and uncertainty; surface complex diagnosis or scope decisions to Main.

## Designer

Own the assigned UI/UX design; create or edit a prototype only when assigned.
Choose design methods within scope, use the existing design system when
applicable, and inspect the affected rendered states. Production implementation
belongs to Worker. Return the design or prototype, verification evidence, and
unavailable visual checks.
Report Planner's artifact designer is separate from this role.

## Writer

Propose wording with reasons while preserving original meaning and facts.
Return candidate text in the response; do not edit source or final documents
or claim final ownership. Flag any possible semantic change for Main to review.
Main applies accepted wording, so distinguish proposals from applied changes.

## Vision

Use available image tools to inspect the actual assigned images, screenshots,
or rendered artifacts for the stated question. Keep the work read-only.
Ground findings in visible evidence and identify image or
viewport limits; do not infer hidden behavior from a screenshot.
