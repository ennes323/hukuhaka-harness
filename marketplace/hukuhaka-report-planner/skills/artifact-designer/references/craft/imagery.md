## Evidence test

Every image must pass the same test as any anchor: which reader question does it answer,
and what evidence does it carry? A photo of a real device state, a physical site, or a
whiteboard original is evidence and follows the same crop-annotate-caption rules as a
screenshot. A photo of hands typing on a laptop answers nothing and costs trust.

## Icons

- Icons are wayfinding, not decoration: a small stable set marking recurring semantic
  roles (warning, external source, per-section markers in a long handbook).
- An icon never carries meaning alone — pair it with its label at least at first use, and
  keep the icon→meaning mapping fixed for the whole document (`color.md` logic applies).
- One visual family, one stroke weight, sized to the text they accompany. Mixed icon sets
  read as a scrapbook.
- The strongest icon budget is small: if every heading has an icon, none of them mark
  anything.

## Illustration

- Justified when it encodes structure that neither a diagram nor a photo can: a physical
  assembly, a spatial cutaway, an annotated hardware panel.
- If the content is boxes-and-relations, it is a diagram (`diagrams.md`) — an illustrated
  metaphor (gears, rockets, mountains) adds style risk and zero evidence.
- Annotate illustrations like any anchor: label the parts the argument uses, not every
  visible part.

## Treatment

- Caption states what the reader is seeing and why it matters — an uncaptioned image is a
  guess assignment.
- Record source and license for any image not produced for this document; unlicensed or
  unattributable imagery does not ship.
- Consistent crop discipline and sizing across sibling images; one image at 40% page width
  and its pair at 90% implies a hierarchy that probably isn't intended.

## Don'ts

- Stock photography of any kind in an evidence document
- An icon per bullet point — bullets are already markers
- Decorative AI-generated hero art standing where evidence should be
- Metaphor illustrations (rocket = launch, gears = process)
- Images carrying text that should be text — unsearchable and unreadable at scale
- Mixed icon families or inconsistent stroke weights
